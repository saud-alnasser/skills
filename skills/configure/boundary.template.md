# The repository boundary

**This session works on one repository. Work for any other leaves as a report.**

| In another repository | |
| --- | --- |
| reading its files, history, issues | **allowed** — a claim is checked by reading what makes it |
| writing or editing a file | **not allowed** |
| planning its work — a spec, a ticket, a design | **not allowed** |
| entering a stage for it | **not allowed** |

The deliverable is the write-up, handed to whoever works there. It is finished when the report is written, not when the change is made.

**A finding about another repository is a report, not an options list.** Never decide architecture silently describes work *this* repository will do; applied to somebody else's it turns a diagnosis into a proposal this session then owns. State what was found, what it costs, and what would close it — **do not offer to do it**, and do not recommend that this session be where it happens.

**Authorization does not transfer.** Being told to fix something is not being told to fix it *here*: the user authorising the work cannot thereby authorise this session to be the place, because that is a fact about where the session stands rather than about what needs doing. Ask if the boundary is genuinely unclear.

**Say it when it is reached**, in that turn — not in a summary afterwards. The failure is never one bad decision; it is a chain of individually authorised steps where none is the obvious place to stop. Naming the crossing is what gives the user somewhere to stop it, and it costs a sentence.

A clean position report licenses none of this. It answers *has this repository moved under me*, never *is this repository mine to change* — and every repository on the disk answers it cleanly to anyone who asks.
