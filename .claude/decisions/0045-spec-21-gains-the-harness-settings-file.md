# Amendment: specification §21 gains `.claude/settings.json`

Orchestration needs one piece of harness configuration to be true of every clone: a worktree-isolated child branches from the repository's default branch unless `worktree.baseRef` is `"head"`, so without it a child works a portion of a claimed ticket against a tree that does not contain the work it is extending — silently, producing plausible code. `/configure` therefore writes `.claude/settings.json`, and §21's canonical layout has to name a file the workflow generates into every repository it configures.

Specification version moves to 1.6.0.

## Considered Options

- **Leave it out, on the ground that §21 lists what the *workflow* owns and this file is the harness's.** Rejected, and it was the first answer: §21 already lists `.gitignore`, which git owns, is read from one exact path, and is generated by `/configure`. ADR 0031 put it there rather than narrowing the layout to exclude it, so "only what the workflow owns" is not the rule §21 follows.
- **Treat `settings.local.json`'s absence from §21 as the precedent.** Rejected: that file is absent because it is Position, and §21 lists nothing gitignored except `position/` itself, annotated as such. `.claude/settings.json` is committed (ADR 0015), so it is a different class and the precedent does not reach it.
- **Ship the divergence and file it as drift.** Rejected: the divergence is known at the moment it is created, and ADR 0029's rule is that a change conforms or amends *in the same change*. Filing it as drift is the silent resolution that rule exists to prevent.

## Consequences

**The layout now contains a file this workflow does not own.** `/configure` merges the key it needs and leaves the rest alone, because a repository may already keep hooks, permissions, or environment there — and removing AEP by deleting `.claude/` now takes those with it, which was not true before.

The `aep/06` assertion comparing the generated tree against §21 is what forced this rather than letting the two drift, which is the check ADR 0031 introduced for the same failure.
