## How the suite was run, and what changed between runs

Each scenario ran once in a fresh harness against `src/` as it stood, two agents at a time. Two were run again on the final text:

- **S1 failed first** (3 commits on the branch instead of 1): the run committed a revised Check item between `aep open` and `aep land`, and land only amended when the branch held exactly one commit. `aep land` now folds everything a quick-lane branch gathered since it forked into the one commit it lands (tested in `tests/aep.test.mjs`). The re-run above passes.
- **S7 ran again** after trip-wire 2 was reworded from "touches a public contract" to "alters an existing public contract": S12's run stopped to ask whether a purely additive export the spec asked for was a stop, which the lane table says it is not. The removal S7 asks for still stops.

Fixes made from what the runs reported, after the runs that surfaced them:

- `index.mjs` refuses an unknown option rather than treating `--help` as a write (S3's reviewer rewrote the index by asking for help).
- `refine` names the scratch draft as its spec when run from `/specify` before the effort opens (S11).
- `/implement` runs `aep close` from the main checkout, never from inside the surface it removes (S12's surface could not be removed while its shell stood in it).
- The git reference seed documents rewording a landed commit with `--fixup=amend:` through `GIT_EDITOR`, since `-m` is refused there (S3, S6); the form was run in a throwaway repository first.
- The version-control seed says ticket branches are the full lane's; quick and standard land on the effort branch (S8).
