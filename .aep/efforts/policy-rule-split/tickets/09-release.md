# chore(dist): release 2.2.0 and reinstall this repository's own tree

## Outcome

Every protocol-owned artifact declares 2.2.0, this repository's `.aep/` is
reinstalled from `src/` rather than hand-edited, the adapter is regenerated, and
the whole suite passes.

## Acceptance Criteria

- [ ] Every artifact under `src/` — `protocol.md`, the four policies, modes,
      skills, agents, templates, and every seed — declares `aep: 2.2.0`, whether
      or not its prose moved. *(spec criterion 13)*
- [ ] `specs.md` declares version 2.2.0 and the release stamps agree with it.
- [ ] `.aep/` is regenerated by running the installer on `src/` in update mode,
      not by editing files under `.aep/`.
- [ ] `node src/scripts/adapters.mjs` regenerates the Claude adapter, and the
      committed adapter is current.
- [ ] `node .aep/scripts/index.mjs` then `validate.mjs` pass, and a second index
      run is byte-identical. *(spec criterion 12)*
- [ ] `node src/scripts/verify.mjs` passes in full.
- [ ] This repository's own `.aep/policies/` holds the four, and its `.aep/rules/`
      holds only `version-control.md` and `authoring.md`, both repository-owned.

## Relevant areas

`src/` — every artifact's `aep:` field. `specs.md` — the version line.
`[[references/build]]` has the commands.

## Constraints

- **Last, and alone.** The stamp touches every file in the distribution, so it
  collides with every other task in this effort. Nothing else may be in flight.
- `.aep/` here is output. A protocol-owned file under `.aep/` that had to be
  hand-edited to make this pass means `src/` is wrong.
- The repository's own `rules/authoring.md` is repository-owned and survives
  untouched — it is the local half of the split working as designed, and a good
  check that the upgrade preserved what it promised.

## Notes

`2.2.0` rather than `3.0.0`: the 2.x layout, the seventeen skills, and the eight
modes all survive, and the change ships a defined migration.
