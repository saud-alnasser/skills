# feat(validate): an artifact outside the tree stops being invisible

## Outcome

`validate.mjs` reports a protocol artifact written outside `.aep/`. "No failures" stops being a possible answer when an effort is sitting at the repository root. It reports and never moves anything, and it stays silent on a consuming repository's own directories that merely share a name.

## Acceptance Criteria

- [x] Requirement 3 / criterion 3: given a fixture with a valid `.aep/` tree and a valid effort at the repository root, `validate.mjs` exits non-zero and names the stray, where it was found, and where it belongs. **Then the same fixture with the stray removed must pass**, so the failure is evidence of the stray rather than of a check that fires on everything. — verified by review against a fixture built with `install.mjs --into` and indexed, rather than against the suite's own: baseline `54 artifacts checked, no failures`, exit 0. Adding `efforts/0001-post-merge-labels/` with `status: accepted` and an evidence tree gave `1 failure(s)`, exit 1, reading `efforts/: sits at the repository root rather than under .aep/, and efforts/0001-post-merge-labels/spec.md declares status: accepted … it belongs at .aep/efforts/`. Deleting only that directory returned the same fixture to `no failures`, exit 0.
- [x] Requirement 4 / criterion 4: given a fixture whose repository root holds a `templates/` directory of ordinary project files, `validate.mjs` reports nothing. This is the case that decides whether the check ships. — verified by review on the same fixture, and wider than the criterion asks: a root `templates/` of `page.hbs`, `partials/header.hbs`, and a frontmatter-less `README.md`, alongside a root `references/paper.md` carrying `title:`/`year:` frontmatter, a root `rules/style.md`, and a root `contexts/legal/retention.md`, all four present at once. `no failures`, exit 0. The check is reachable on all four names, which the arms below show by firing on each of them.
- [x] Requirement 4: recognition is by the contract, never by directory name, and **every arm reads content**. A root `efforts/` is a finding only where a child holds a `spec.md` whose `status:` is in `SPEC_STATUSES`; a root `policies/`, `skills/`, `agents/`, or `templates/` only where a file inside carries a `use-when`; a root `scripts/` only where a file inside is byte-identical to the script this release ships at that path; a root `rules/`, `contexts/`, or `references/` only where a file inside carries a `use-when` at the depth the artifacts policy allows. — verified by review against a fresh `install.mjs --into` fixture, indexed, baseline `55 artifacts checked, no failures`, exit 0. Each arm was flipped in both directions on content alone, with the filename held fixed where a name could confound it. `agents/researcher.md` — a name this release ships — is silent as plain Markdown and reports `agents/researcher.md carries a use-when` the moment frontmatter is added, then silent again when it is removed; `agents/rota-reviewer.md`, a name this release has never shipped, reports on the same `use-when`. The same flip holds for `policies/execution.md`, `skills/plan.md`, and `templates/spec.template.md`. Depth: `skills/plan/depth.md` reports, `skills/a/b/c.md` does not, `policies/x/y.md` does not. `scripts/`: a byte-identical copy of `.aep/scripts/index.mjs` reports `scripts/index.mjs is byte-identical to the script this release ships`, one appended newline returns it to `no failures`, and the same pair holds for `validate.mjs`; a shipped script copied to the unshipped name `scripts/build.mjs` is silent. `efforts/` still reports on `status: accepted`. `USE_WHEN_DEPTHS` is read by `strayEvidence` and by nothing else, so widening it moved no other check.
- [x] Requirement 4: a consuming repository's own root `scripts/` and `agents/` report nothing, **tested as a fixture rather than claimed**. An empty `scripts/index.mjs`, a `scripts/index.mjs` holding an ordinary build entrypoint, and an `agents/researcher.md` about something else are each silent, despite every one of those names being a name this release ships. This is the false positive that reached review and it is what the arm above exists to prevent. — verified by review on the same fixture, all at once and wider than the criterion asks: a zero-byte `scripts/index.mjs`, then that file holding `console.log("our build entrypoint");` alongside a `scripts/contract.mjs` of `export const ROUTES = [];`, an `agents/researcher.md` about an analyst rota, a `policies/execution.md` about PTO, a `templates/spec.template.md` of Handlebars, and a `skills/plan.md` about sprint planning — every one of those a path the manifest names — present together: `55 artifacts checked, no failures`, exit 0. The suite carries it rather than the review claiming it: `node src/scripts/verify.mjs --section strays` is 14 passed, 0 failed, and the fixture is load-bearing — restoring the original defect (the `scripts` arm deciding on `isProtocolPath` alone) fails `a repository's own root scripts/ is not a finding, empty or ordinary` on the zero-byte file, and killing the arm outright fails `a root scripts/ holding a byte-identical copy of a shipped script fails`, so a passing run is not an arm that has quietly stopped firing.
- [x] The reported path is relative to the repository root, not to `.aep/`. Every other failure in this file is tree-relative, and printing a tree-relative path for a stray would name the correct location while reporting the incorrect one. — verified by review by putting a stray and an ordinary failure in one run: `efforts/inside/spec.md: spec status is "bogus"` is tree-relative and resolves under `.aep/`, while the stray's `efforts/` and its evidence `efforts/0001-post-merge-labels/spec.md` resolve from the repository root, where the file is and where `.aep/efforts/0001-post-merge-labels` does not exist. The failure says which root it counts from in its own words, which is what keeps the two readings apart.
- [x] The upgrade notice for this behaviour lands with it: a tree that validated before can fail after, and the fix is a move the reader makes. — verified by review by running the notice out of the release path rather than reading it in `payload.mjs`: a fixture tree whose `protocol.md` declares `version: 3.0.0`, then `install.mjs --update --dry-run`, printed `1 thing to check, crossing these releases: 3.1.0` followed by the whole notice, including "A tree that validated yesterday can fail today" and "The fix is to move the directory under .aep/ and run validate again". `collectNotices` gates on `precedes(declared, since)`, so a tree declaring nothing gets it too and one already on 3.1.0 does not.

**Read against 3.2.0, which shipped from `main` after this was verified.** The run above observed a gate of `3.1.0` and the gate is still `3.1.0`, so nothing here is stale. What changed is who it reaches: a tree on 3.3.0 is already past `3.1.0` and would be shown nothing, and this notice ships in 3.4.0. Moving the gate now is not the fix, because a gate above the version of record fails the install fixture in the other direction. `[[efforts/48-artifact-paths/tickets/09-release]]` carries the repin, in the same change that writes the version. The mechanism this criterion asked about, `collectNotices` gating on `precedes(declared, since)`, is what both directions are evidence of.

## Relevant areas

`src/scripts/validate.mjs` (a `checkStrays(root)` beside `checkStructure`, called from `main`), `src/scripts/payload.mjs` (`NOTICES`), `src/scripts/verify.mjs` (the two fixtures), and `specs.md` where the validator's conformance requirements are stated.

## Constraints

**It reports and does not move.** Relocating somebody's files is a write nobody requested and the correct destination is not always inferable.

The scan reaches the repository root's immediate children and no deeper. A full walk was rejected in `[[efforts/48-artifact-paths/plan]]` on the evidence that it would flag this repository's own `src/skills/` and `src/policies/`.

## Notes

`resolveAepRoot` returns the directory holding `protocol.md`, so the repository root is its parent. Nothing else in this file looks outside the root, which is why the whole defect was representable.

The false-positive fixture is not optional politeness. A check that fires on an ordinary repository is worse than the defect, because it teaches people the validator is noise, and after that it catches nothing at all.

The suite moves in the same pass, and the guard is broken deliberately once (`[[rules/authoring]]`).

**Re-cut 2026-08-24, after review.** The protocol-directory arm was written here as `isProtocolPath` and nothing else, which is a filename match reading no content, and it fired on an ordinary repository's root `scripts/index.mjs`. The correctness reviewer ticked the criterion as worded and reported the contradiction with spec requirement 4 rather than settling it, which is why the ticket rather than the build is what changed. The corrected gate and the two rejected alternatives are in `[[efforts/48-artifact-paths/plan]]`; the reproduction is in `[[efforts/48-artifact-paths/evidence/research/protocol-directory-shape-gate]]`.
