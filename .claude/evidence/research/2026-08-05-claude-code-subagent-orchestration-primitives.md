# What orchestration primitives does Claude Code provide for sub-agents, and what does a sub-agent inherit?

Verified against: Claude Code 2.1.222 (`claude --version`), docs.claude.com as of 2026-08-05
Status: four open questions remain — path-scoped `.claude/rules/` inside a sub-agent, the Agent tool's published input schema, `.claude/rules/` in the sub-agent load list beyond the phrase "project rules", and the env-vars page entries for three limit variables (corroborated indirectly, not read directly).

> Note on URLs: `https://docs.claude.com/en/docs/claude-code/*` now 301-redirects to `https://code.claude.com/docs/en/*`. Citations below use the canonical post-redirect URLs.

## Answer

A sub-agent is **not** a bare agent and **not** a continuation of the parent. It starts with a fresh, isolated context window that contains exactly five things: its own system prompt (the agent file's markdown body, plus environment details — *not* the full Claude Code system prompt), the delegation prompt the parent wrote, the whole `CLAUDE.md` hierarchy the parent loaded (managed policy, `~/.claude/CLAUDE.md`, project rules, `CLAUDE.local.md`), a git-status snapshot, and any skills named in its `skills` frontmatter. It does **not** get the parent's conversation history, tool results, system prompt, output style, or auto memory. The two exceptions are the built-in `Explore` and `Plan` agents, which deliberately skip `CLAUDE.md` and git status with no way to turn that back on, and a **fork** (`/subtask`), which inherits the entire parent conversation, system prompt, tools, model, and prompt cache. So a project's `CLAUDE.md` and its always-on rules *do* reach a custom sub-agent, but everything the parent learned in-session does not — anything the sub-agent needs from the conversation must be written into the Agent tool's `prompt` string, which is the only parent-to-child channel.

The return channel is deliberately narrow: a single text result. The parent never sees intermediate tool calls or outputs, and there is **no structured-output mechanism** for sub-agent results — the contract is a string, plus an `agentId: <id>` trailer that makes the agent resumable via `SendMessage`. Orchestration primitives that do exist and are documented: per-agent tool allow/deny lists, `permissionMode`, `model`, `maxTurns`, `effort`, preloaded `skills`, per-agent `hooks` and `mcpServers`, persistent `memory`, background-vs-foreground execution (background is the default as of v2.1.198, and background runs get a *narrower* built-in tool set), git-worktree isolation via `isolation: worktree`, and three independent numeric limits — 20 concurrent sub-agents, 200 per session, and 3 layers of nesting. Without `isolation: worktree`, sub-agents share the parent's working directory and can collide; that is what worktree isolation exists to prevent.

## Findings

### Inheritance

- Each sub-agent starts with a fresh, isolated context window: "It doesn't see your conversation history, the skills you've already invoked, or the files Claude has already read. Claude composes a delegation message that summarizes the task, and the subagent works from there." — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "What loads at startup"
- A non-fork sub-agent's initial context contains exactly five items: **system prompt** (the agent's own prompt plus appended environment details, "not the full Claude Code system prompt"), **task message** (the delegation prompt), **CLAUDE.md files**, **git status**, **preloaded skills**, plus a **sibling roster** when it has `SendMessage` and another agent is named (v2.1.206+). — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "What loads at startup"
- (a) Project `CLAUDE.md` **is** inherited, and (b) user-level `~/.claude/CLAUDE.md` **is** inherited: the sub-agent receives "every level of the CLAUDE.md hierarchy the main conversation loads, including `~/.claude/CLAUDE.md`, project rules, `CLAUDE.local.md`, and managed policy files." — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "What loads at startup"
- A project `CLAUDE.md` may live at either `./CLAUDE.md` or `./.claude/CLAUDE.md`; both are the same "Project instructions" scope, so both ride the hierarchy into the sub-agent. — [How Claude remembers your project](https://code.claude.com/docs/en/memory), "Choose where to put CLAUDE.md files"
- (c) Rule files **without** `paths:` frontmatter are inherited: "Rules without `paths` frontmatter are loaded at launch with the same priority as `.claude/CLAUDE.md`" — so they are part of the launch-loaded hierarchy the phrase "project rules" names in the sub-agent load list. — [How Claude remembers your project](https://code.claude.com/docs/en/memory), "Set up rules"
- (c, cont.) Rule files **with** `paths:` frontmatter load by a different mechanism: "Path-scoped rules trigger when Claude reads files matching the pattern, not on every tool use." The documentation never states whether this trigger fires inside a sub-agent's own Read calls. — [How Claude remembers your project](https://code.claude.com/docs/en/memory), "Path-specific rules" — **the documentation is silent on the sub-agent case**; see Open questions.
- User-level rules in `~/.claude/rules/` "apply to every project on your machine" and are "loaded before project rules, giving project rules higher priority". — [How Claude remembers your project](https://code.claude.com/docs/en/memory), "User-level rules"
- (d) The parent's conversation history is **not** inherited: the sub-agent "doesn't receive" "the parent's conversation history or tool results" or "the parent's system prompt". — [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents), "What subagents inherit"
- The only parent→child data channel is the prompt string: "The only content you pass from parent to subagent is the Agent tool's prompt string, so include any file paths, error messages, or decisions the subagent needs directly in that prompt." — [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents), "What subagents inherit"
- The built-in `Explore` and `Plan` agents are the **only** agents that skip `CLAUDE.md` and git status, and this cannot be changed: "Explore and Plan are the only subagents that omit CLAUDE.md and git status. There is no frontmatter field or per-agent setting to change which agents skip them." — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "What loads at startup"
- Also **not** inherited: output style ("a subagent runs its own system prompt, so your output style doesn't shape its responses"), the main conversation's auto memory, and the parent's context-window size (a sub-agent's window "is sized by its own model, not the parent's"). — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "What loads at startup"
- Auto memory is confirmed excluded from the parent side too: "The main conversation's auto memory isn't loaded into subagents; the exception is a fork". — [How Claude remembers your project](https://code.claude.com/docs/en/memory), "How it works"
- A **fork** inherits everything: "A fork is a subagent that inherits the entire conversation so far instead of starting fresh… a fork sees the same system prompt, tools, model, and message history as the main session". Its first request also reuses the parent's prompt cache. — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Fork the current conversation"
- Permission context is inherited and only partly overridable: "Subagents inherit the permission context from the main conversation and can override the mode… If the parent uses `bypassPermissions` or `acceptEdits`, this takes precedence and can't be overridden. If the parent uses auto mode, the subagent inherits auto mode and any `permissionMode` in its frontmatter is ignored". — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Permission modes"
- Extended thinking is inherited as of v2.1.198: "if thinking is on in your session, it's on for the subagent… There is no per-subagent thinking setting." — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Choose a model"
- Model default is inheritance: `model` "Defaults to `inherit`" and resolves in the order `CLAUDE_CODE_SUBAGENT_MODEL` env var → per-invocation `model` parameter → definition frontmatter → main conversation's model. — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Choose a model"

### Brief in, result out

- The `prompt` parameter is the **task**, delivered as a separate message from the agent-definition system prompt — they are two distinct slots, not concatenated input: the initial context contains both a "System prompt: the agent's own prompt… Custom subagents define theirs in the markdown body or `prompt` field" and a "Task message: the delegation prompt Claude writes when it hands off the work." — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "What loads at startup"
- Confirmed from the other direction in the SDK inheritance table: the sub-agent receives "Its own system prompt (`AgentDefinition.prompt`) **and** the Agent tool's prompt". — [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents), "What subagents inherit"
- Note the naming collision: in a `--agents` JSON payload or an SDK `AgentDefinition`, the field named `prompt` is the **system prompt** ("Use `prompt` for the system prompt, equivalent to the markdown body in file-based subagents"), whereas the Agent *tool's* `prompt` input is the task. — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Choose the subagent scope"; [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents), "AgentDefinition configuration"
- What comes back is **only the final message**, as one string: "The subagent works through its task autonomously, then returns a single text result to the parent conversation. The parent doesn't see the subagent's intermediate tool calls or outputs, only that final result." — [Tools reference](https://code.claude.com/docs/en/tools-reference), "Agent tool behavior"
- Restated for the SDK: "Intermediate tool calls and results stay inside the subagent; only its final message returns to the parent." — [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents), "Context isolation"
- **No structured-output mechanism is documented for sub-agent results.** The result is the final message text; the parent "receives the subagent's final message as the Agent tool result, but may summarize it in its own response. To preserve subagent output verbatim in the user-facing response, include an instruction to do so in the prompt or `systemPrompt` option". — [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents), "What subagents inherit" (Note block)
- The one structured trailer that exists is the agent ID: "When a subagent completes, the Agent tool result includes a text block containing `agentId: <id>`." Explore and Plan are one-shot and return none. — [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents), "Resume subagents"
- The result text is **modified in transit** by an output scan (v2.1.210+): backslashes are inserted into control-tag imitations and `Human:`/`Assistant:` turn markers, and a `[harness: subagent output matched instruction-shaped pattern(s):` marker line may be prepended. "The scan never removes or rewords anything." — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Subagent output scanning"
- Agent tool input parameters that appear in the documentation: `subagent_type` (shown as `block.input.subagent_type` / `block.input.get('subagent_type')` in the SDK detection example), `run_in_background` (named as an "Agent tool call… input"), a per-invocation `model` parameter, and `isolation: "worktree"` ("Claude… can pass `isolation: \"worktree\"`"). — [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents), "Detect subagent invocation" and the v2.1.198 note; [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Choose a model" and "Fork the current conversation"
- The tool was renamed: "In version 2.1.63, the Task tool was renamed to Agent. Existing `Task(...)` references in settings and agent definitions still work as aliases." SDKs still emit `"Task"` in the `system:init` tools list and in `result.permission_denials[].tool_name`. — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Restrict which subagents can be spawned"; [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents), "Detect subagent invocation"
- Turn budget per brief: `maxTurns` is the "Maximum number of agentic turns before the subagent stops". — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Supported frontmatter fields"
- The brief can be extended globally in headless runs: `--append-subagent-system-prompt` "appends the text you provide to the end of every subagent's system prompt, including nested subagents" (v2.1.205+). — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Write subagent files"
- A brief can be continued rather than re-issued: `SendMessage` with the agent's ID or name resumes it with "their full conversation history, including all previous tool calls, results, and reasoning". A completed sub-agent auto-resumes in the background without a new `Agent` invocation. — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Resume subagents"
- Failure is reported as failure, not as findings (v2.1.199+): a foreground sub-agent cut off by an API error returns its partial output "with a note that the subagent was cut off"; one that produced nothing fails with `Agent terminated early due to an API error`. — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "API errors in subagents"

### Workspace isolation

- By default a sub-agent **shares the parent's working directory**: "A subagent starts in the main conversation's current working directory. Within a subagent, `cd` commands don't persist between Bash or PowerShell tool calls and don't affect the main conversation's working directory." — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Write subagent files"
- Collisions are therefore possible without isolation, and worktrees are the documented remedy: "Subagents can run in their own worktrees so parallel edits don't conflict." — [Run parallel sessions with worktrees](https://code.claude.com/docs/en/worktrees), "Isolate subagents with worktrees"
- `isolation: worktree` gives "a temporary git worktree… an isolated copy of the repository branched **by default from your default branch rather than the parent session's `HEAD`**. The worktree is automatically cleaned up if the subagent makes no changes." — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Supported frontmatter fields"
- To branch from in-progress work instead, set `worktree.baseRef` to `"head"`: "Use this when isolating subagents that need to operate on in-progress work." Default is `"fresh"` (repository default branch on the remote). — [Run parallel sessions with worktrees](https://code.claude.com/docs/en/worktrees), "Choose the base branch"
- Isolation is enforced, not merely conventional: a worktree-isolated sub-agent "runs its Bash and PowerShell commands inside its worktree", a command whose working directory resolves to the main checkout "fails with an error", and for Bash "a command that redirects git into the main checkout fails with an error, whether it uses `git -C`, `--git-dir`, a `GIT_DIR` or `GIT_WORK_TREE` variable, or a `cd` into the main checkout first" (v2.1.203/v2.1.210 hardening). — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Write subagent files"
- Cleanup: worktrees with changes survive until a periodic sweep older than `cleanupPeriodDays` removes them, and the sweep "skips a worktree that still holds work". "While an agent is running, Claude runs `git worktree lock` on its worktree so that concurrent cleanup cannot remove it." — [Run parallel sessions with worktrees](https://code.claude.com/docs/en/worktrees), "Clean up subagent and background-session worktrees"
- Worktrees still share `.git`, project-scope plugins, and saved permission approvals with the main checkout. — [Run parallel sessions with worktrees](https://code.claude.com/docs/en/worktrees), "What worktrees share with the main checkout"
- Background is the **default** execution mode as of v2.1.198: "subagents run in the background by default. Claude runs a subagent in the foreground when it needs the result before continuing." `background: true` in frontmatter forces background always. — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Run subagents in foreground or background"
- Background changes the tool pool, not just the timing: a background sub-agent "keeps every MCP tool but only these built-in tools: `Read`, `Grep`, `Glob`, `Bash`, `PowerShell`, `Edit`, `Write`, `NotebookEdit`, `WebFetch`, `WebSearch`, `TodoWrite`, `Skill`, `ToolSearch`, `EnterWorktree`, `ExitWorktree`, `Monitor`, `TaskStop`, `SendMessage`, and `Artifact`" — "so the same definition can resolve to different tools in the foreground and the background." Forks are exempt from both filters. — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Available tools"
- Concurrency limit: "By default, when 20 subagents are running in a session, spawning another with the Agent tool fails with `Concurrent subagent limit reached`… To change the limit, set `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` to any positive whole number. Sessions with ultracode active are exempt" (v2.1.217+). — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Concurrent subagent limit"
- Session total limit: "By default, Claude can spawn at most 200 subagents per session… set `CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION` to any positive whole number; there is no upper bound, but the limit can't be turned off" (v2.1.212+). `/clear` resets the count. — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Session subagent limit"
- Background sub-agents have a stall timeout: `CLAUDE_ASYNC_AGENT_STALL_TIMEOUT_MS`, "Default `600000` (10 minutes). The timer resets on each streaming progress event; if no progress arrives within the window, the subagent is aborted and the task is marked failed, surfacing any partial result to the parent". — [Environment variables](https://code.claude.com/docs/en/env-vars)
- Background permission prompts surface in the parent session as of v2.1.186, naming the asking sub-agent; Esc denies one tool call without stopping it. Before v2.1.186 they auto-denied. — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Run subagents in foreground or background"
- Background results are not readable early: "A background subagent's results reach Claude as a completion notification in a later turn. Claude waits for that notification before reporting the subagent's results" (v2.1.211+). — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Run subagents in foreground or background"
- All background task functionality can be disabled with `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`, which "takes precedence over fork mode and keeps subagents in the foreground". — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Run subagents in foreground or background"

### Agent definitions

- Definitions are Markdown with YAML frontmatter; "The frontmatter defines the subagent's metadata and configuration. The body becomes the system prompt that guides the subagent's behavior." — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Write subagent files"
- Full frontmatter field list (only `name` and `description` are required): `name`, `description`, `tools`, `disallowedTools`, `model`, `permissionMode`, `maxTurns`, `skills`, `mcpServers`, `hooks`, `memory`, `background`, `effort`, `isolation`, `color`, `initialPrompt`. — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Supported frontmatter fields"
- Field semantics worth naming: `tools` (allowlist; inherits all sub-agent-available tools if omitted), `disallowedTools` (denylist, applied first — "If both are set, `disallowedTools` is applied first, then `tools` is resolved against the remaining pool. A tool listed in both is removed"), `permissionMode` (`default`/`acceptEdits`/`auto`/`dontAsk`/`bypassPermissions`/`plan`/`manual`), `memory` (`user`/`project`/`local` persistent directory), `effort` (`low`…`max`, overrides session effort), `color` (8 named colors), `initialPrompt` (only when the agent runs as the main session agent). — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Supported frontmatter fields" and "Control subagent capabilities"
- `name` constraints: "Unique identifier using lowercase letters and hyphens… The filename doesn't have to match. Names can't contain `:`… Claude Code doesn't load a file whose name contains one" (v2.1.218+). Hooks receive it as `agent_type`. — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Supported frontmatter fields"
- Scope and precedence, highest to lowest: **1** managed settings (organization-wide), **2** `--agents` CLI flag (session), **3** `.claude/agents/` (project), **4** `~/.claude/agents/` (user), **5** a plugin's `agents/` directory. "When multiple subagents share the same name, Claude Code uses the one from the higher-priority location." — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Choose the subagent scope"
- Project scope walks up the tree: "every `.claude/agents/` between there and the repository root is scanned… when more than one of these nested directories defines the same `name`, Claude Code uses the definition closest to the working directory" (v2.1.178+). `--add-dir` directories are also scanned. — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Choose the subagent scope"
- Duplicate names **within** one directory have no defined winner: "Claude Code loads only one of them, chosen by filesystem read order rather than a documented precedence." `/doctor` reports these. — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Choose the subagent scope"
- Per-call overrides beat the definition only for `model`, and the env var beats both: resolution is `CLAUDE_CODE_SUBAGENT_MODEL` → per-invocation `model` parameter → definition's `model` frontmatter → main conversation's model. A per-invocation `model` also persists across resume (v2.1.211+). — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Choose a model"
- Plugin definitions are restricted: "For security reasons, plugin subagents don't support the `hooks`, `mcpServers`, or `permissionMode` frontmatter fields. These fields are ignored when loading agents from a plugin." — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Choose the subagent scope"
- The plugin reference lists the supported set positively: "Plugin agents support `name`, `description`, `model`, `effort`, `maxTurns`, `tools`, `disallowedTools`, `skills`, `memory`, `background`, and `isolation` frontmatter fields. The only valid `isolation` value is `\"worktree\"`." Location is the `agents/` directory in the plugin root. — [Plugins reference](https://code.claude.com/docs/en/plugins-reference), "Agents"
- Plugin sub-directories become part of the identifier: "a file at `agents/review/security.md` in plugin `my-plugin` registers as `my-plugin:review:security`" — unlike project/user scope, where "identity comes only from the `name` frontmatter field". — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Choose the subagent scope"
- CLI-defined agents accept the same fields as JSON, with `prompt` standing in for the markdown body: `description`, `prompt`, `tools`, `disallowedTools`, `model`, `permissionMode`, `mcpServers`, `hooks`, `maxTurns`, `skills`, `initialPrompt`, `memory`, `effort`, `background`, `isolation`, `color`. — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Choose the subagent scope"
- SDK `AgentDefinition` is a near-mirror with `description` and `prompt` required, and adds explicit types: `tools: string[]`, `disallowedTools: string[]`, `model: string`, `skills: string[]`, `memory: 'user'|'project'|'local'`, `mcpServers`, `initialPrompt`, `maxTurns: number`, `background: boolean`, `effort`, `permissionMode`. "Programmatically defined agents take precedence over filesystem-based agents with the same name." — [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents), "AgentDefinition configuration" and "Filesystem-based definition"
- Definitions are hot-reloaded: "Claude Code watches `~/.claude/agents/` and `.claude/agents/`… the next delegation uses the updated definition, with no restart needed" — except for a scope's *first* file in a newly created directory, and sessions started with `--disable-slash-commands`. — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Write subagent files"
- Local shape evidence (primary for shape, not contract): `C:\Users\saud-alnasser\.claude\plugins\marketplaces\claude-plugins-official\plugins\claude-security\agents\explore.md` carries `name`, `description`, `model: sonnet`, `effort: xhigh`, `color: cyan`, `tools: Read, Glob, Grep, Bash` — a real plugin agent using the `effort` and `color` fields and a comma-separated `tools` string.

### Recursion and skills

- Sub-agents **can** spawn sub-agents by default, three layers deep: "By default, a subagent can spawn subagents of its own, up to three layers below the main conversation. At the depth limit, Claude Code withholds the `Agent` tool from every subagent except a fork… A fork at the limit keeps `Agent` in its inherited tool list, but the tool returns an error instead of spawning." — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Let subagents spawn their own subagents"
- The depth limit is configurable via `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`; "Set `1` to turn nesting off." History matters here: v2.1.172–v2.1.216 defaulted to five and was not configurable; v2.1.217–v2.1.218 defaulted to one; v2.1.219 raised it to three. — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Let subagents spawn their own subagents"
- Only the top-level summary comes back: "Only the top-level subagent's summary returns to you." — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Let subagents spawn their own subagents"
- To stop one agent from nesting, "omit `Agent` from its `tools` list or add it to `disallowedTools`." — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Let subagents spawn their own subagents"
- The `Agent(type1, type2)` allowlist syntax **does not work in a sub-agent definition**: "The `Agent(agent_type)` allowlist syntax applies only to an agent running as the main thread with `claude --agent`. In a subagent definition, listing `Agent` in `tools` lets that subagent spawn subagents of its own while the depth limit allows it, but any type list inside the parentheses is ignored." — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Restrict which subagents can be spawned"
- Sub-agents **can** invoke Skills: `Skill` is in the built-in tool set retained by background sub-agents, and "without it [the `skills` field], the subagent can still discover and invoke project, user, and plugin skills through the Skill tool during execution. To prevent a subagent from invoking skills entirely, omit `Skill` from the `tools` list or add it to `disallowedTools`." — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Available tools" and "Preload skills into subagents"
- Since custom slash commands are now skills — "A file at `.claude/commands/deploy.md` and a skill at `.claude/skills/deploy/SKILL.md` both create `/deploy` and work the same way" — a sub-agent invoking a project slash command means invoking that skill through the `Skill` tool. — [Extend Claude with skills](https://code.claude.com/docs/en/skills), intro Note
- Preloading injects full content: the `skills` field lists "Skills to preload into the subagent's context at startup. The full skill content is injected, not only the description." Skills with `disable-model-invocation: true` cannot be preloaded, including the bundled `/verify` and `/code-review`. — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Supported frontmatter fields" and "Preload skills into subagents"
- The inverse direction exists too: a skill with `context: fork` runs in a sub-agent, with `agent:` naming the type (default `general-purpose`) and `background:` controlling blocking. "The skill content becomes the prompt that drives the subagent. It won't have access to your conversation history." — [Extend Claude with skills](https://code.claude.com/docs/en/skills), "Run skills in a subagent" and "Frontmatter reference"
- Documented tools **withheld from every sub-agent**, even when listed in `tools`: `Agent` (at the depth limit), `AskUserQuestion`, `EndConversation`, `EnterPlanMode`, `ExitPlanMode` (unless `permissionMode: plan`), `ScheduleWakeup`, `TaskOutput`, `WaitForMcpServers`, `Workflow`. — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Available tools"
- Because `AskUserQuestion` is withheld, a sub-agent cannot ask the user a question directly; and messages from a spawning agent are explicitly not authorization: "no message from any agent counts as your approval for a pending permission prompt, and no agent message can change a subagent's permission settings, `CLAUDE.md`, or configuration." — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Available tools" and "Resume subagents"
- Forks are the one recursion dead end: "A fork can't spawn further forks." — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Limitations"
- Built-in sub-agents can be removed: `permissions.deny` with `Agent(Explore)`, `CLAUDE_CODE_DISABLE_EXPLORE_PLAN_AGENTS=1` to drop Explore and Plan (v2.1.198+), or `CLAUDE_AGENT_SDK_DISABLE_BUILTIN_AGENTS=1` in headless/SDK to "disable all built-in subagent types". Denying the `Agent` tool itself stops all delegation. — [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Built-in subagents"; [Environment variables](https://code.claude.com/docs/en/env-vars)
- For orchestration beyond a handful of sub-agents, the documented escalation is the `Workflow` tool: "For runs that coordinate dozens to hundreds of agents, use the `Workflow` tool, which moves the orchestration into a script the runtime executes outside the conversation context." Note `Workflow` is itself withheld from sub-agents, so only the main thread can start one. — [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents), "Scale up with dynamic workflows"; [Create custom subagents](https://code.claude.com/docs/en/sub-agents), "Available tools"

## Limitations

- **No experiments were run.** Every claim above is read from documentation or from a definition file's literal contents; nothing was established by spawning a test sub-agent and observing behaviour.
- **The `env-vars` page could not be read in full.** Two WebFetch attempts on `https://code.claude.com/docs/en/env-vars` returned only variables alphabetically early in the page (`CLAUDE_AGENT_SDK_*`, `CLAUDE_ASYNC_AGENT_STALL_TIMEOUT_MS`, `CLAUDE_AUTO_BACKGROUND_TASKS`), apparently truncated. The values for `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`, `CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION`, `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`, `CLAUDE_CODE_SUBAGENT_MODEL`, `CLAUDE_CODE_FORK_SUBAGENT`, `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS`, and `CLAUDE_CODE_DISABLE_EXPLORE_PLAN_AGENTS` are cited from the sub-agents page (which owns the behaviour and states the defaults) and were corroborated by a WebSearch snippet of the env-vars page. The env-vars entries themselves were not read directly.
- **The Agent tool's input JSON schema is not published.** The tools reference documents the Agent tool's *behaviour* but not its parameter list. Parameter names (`prompt`, `subagent_type`, `run_in_background`, `model`, `isolation`) were assembled from prose and SDK code examples across the sub-agents and SDK pages. A `description` parameter is implied by the transcript rendering "`code-improver (Suggest code improvements)`" but is never named in the documentation.
- **"Project rules" is the only wording connecting `.claude/rules/` to sub-agent startup.** The sub-agents page lists "project rules" inside the CLAUDE.md hierarchy; the memory page establishes that non-`paths` rules load at launch at the same priority as `.claude/CLAUDE.md`. Joining those two statements is a one-step inference, not a single sentence anyone wrote. Nothing addresses `~/.claude/rules/` in a sub-agent by name.
- **Version-sensitive.** A large share of this behaviour changed within the last ~50 patch versions (background-by-default at v2.1.198, depth default at v2.1.219, concurrency limit at v2.1.217, session limit at v2.1.212, output scanning at v2.1.210). Anything read here is true for 2.1.222 and should be re-checked against the changelog after an upgrade.
- **Not checked:** agent teams (`/docs/en/agent-teams`), agent view / background sessions (`/docs/en/agent-view`), dynamic workflows (`/docs/en/workflows`), and the hooks reference beyond what the sub-agents page quotes. Each is a neighbouring orchestration surface with its own inheritance and limits, and each was out of scope for the five sub-questions.
- **No secondary sources were used.** No claim above rests on a blog post or community write-up.
