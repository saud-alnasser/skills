# feat(knowledge): designs gain a generated index where the directory is flat

Status: open
Blocked by: 04, 05
Part of: declared-fields

## Problem

In a repository configured by AEP, specs land flat in the designs directory and accumulate without partition — there is no per-effort folder naming them, so finding the spec that governs an area means reading titles. This repository is the exception: it puts one spec per effort under the effort's own directory, which already names it, so the cost is invisible here and real everywhere else.

That asymmetry is the trap. A format judged only against the repository that builds AEP gets built for the one tree where it is least needed.

## Outcome

Designs gain an index generated from the fields ticket 04 gives specs — status and sources, which together answer the question a reader of a flat directory asks first: which of these is live, and what does it govern.

This repository generates the same index over its own specs even though its effort directories partition them, because a format with two versions is the drift this effort exists to remove. The index is cheap here and load-bearing elsewhere.

Templates first, per ADR 0025.

## Acceptance

- An index over the designs directory is generated by the regenerator from ticket 05 and covered by the suite's comparison.
- The index carries each spec's status, so a reader learns which are live without opening one — the same property the decision index has.
- A spec that declares no fields cannot appear in a regeneration.
- This repository's own specs are indexed by the same mechanism, wherever its tracker policy says they live — no second format for the repository that builds the framework.
- The configured-repository path is exercised, not assumed: the templates produce a working index in a tree where the designs directory is flat.
